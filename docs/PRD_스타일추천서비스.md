# 1. 서비스 개요

- **서비스명**: STYLE:ME (가칭 · 워크시트명 "AI 기반 개인 맞춤형 스타일 추천 서비스")
- **한 줄 설명**: 나의 성향과 취향, 상황을 입력하면 데이터를 바탕으로 어울리는 스타일을 찾아주는 AI 서비스
- **해결하려는 문제**: 중·고등학생이 "무엇을 입을까"를 판단할 자기 기준이 없어, 익숙한 옷과 유행만 반복하게 되는 상황
- **핵심 사용자**: 자신의 성향과 개성에 맞는 스타일을 찾고 싶은 중·고등학생
- **주요 사용 상황**
  - 수업 중: QR코드로 접속해 조건을 선택하고 결과를 친구와 비교
  - 수업 밖: 면접·발표·체험학습·약속 등 평소와 다른 상황의 옷차림을 준비할 때

# 2. 문제 정의

**현재 방식**
SNS에서 코디를 찾아보거나, 친구에게 물어보거나, 쇼핑몰의 유행 스타일을 참고한다.

**현재 방식의 문제**

1. 남에게 어울리는 스타일은 알 수 있지만, 자기 성향이 반영된 추천은 받기 어렵다.
2. "예쁜가"는 판단해도 "나와 맞는가"를 판단할 기준이 없다.
3. 익숙한 옷을 반복하게 되어 새로운 스타일을 시도할 기회가 적다.
4. 상황(TPO)과 자기 취향을 동시에 고려하기 어렵다.

**해결하려는 핵심 문제**
학생이 자신의 성향·선호·상황을 근거로 스타일을 선택할 수 있는 **판단 기준**을 제공한다.

**기대 효과**

- "무엇을 입을까"라는 막연한 고민이 "나에게 어떤 스타일이 어울릴까"라는 구체적 탐색으로 바뀐다.
- 추천 이유를 읽으며 자기 취향을 언어로 설명할 수 있게 된다.
- 친구와 결과를 비교하며 개성의 차이를 인식한다.

# 3. 사용자 시나리오

QR코드/링크 접속 (로그인 없음)
→ 7가지 조건 선택 (MBTI · 성별 · 나이대 · 체형 · 계절 · 상황 · 선호 스타일)
→ **[AI 코디 추천 받기]** 클릭
→ 버튼 비활성화 + "분석 중..." 표시
→ 서버가 시트에서 MBTI 기준 데이터 조회 → 사용자 입력과 합쳐 Gemini 호출
→ 오른쪽에 결과 표시 (스타일 방향 + 코디 표 + 추천 이유 + 실제 착용샷 이미지)
→ 결과가 시트에 자동 저장
→ 학생은 결과를 캡처/공유하거나, 조건을 바꿔 다시 추천받음

# 5. 화면 구성

## 5.1 메인 화면 (단일 페이지, 좌·우 2단 / 모바일에서는 상·하)

- **화면 목적**: 조건 입력과 결과 확인을 한 화면에서 끝낸다.
- **주요 구성 요소**
  - 상단: 서비스명, 한 줄 설명
  - 왼쪽(입력 영역)
    - MBTI 선택 (16유형)
    - 성별 (여성 / 남성 / 선택 안 함)
    - 나이대 (중학생 / 고등학생)
    - 체형 (마른 / 보통 / 통통 / 근육형)
    - 계절 (봄 / 여름 / 가을 / 겨울)
    - 상황 (일상 / 등교 / 발표·면접 / 체험학습·여행 / 약속·데이트 / 행사)
    - 선호 스타일 (미니멀 / 캐주얼 / 스트릿 / 클래식 / 러블리 / 댄디)
    - `[AI 코디 추천 받기]` 버튼
  - 오른쪽(결과 영역)
    - 초기: "조건을 선택하고 버튼을 눌러보세요" 안내
    - 로딩: "분석 중..." + 스피너
    - 완료: ① 스타일 방향 ② 코디 표 ③ 추천 이유 ④ 색상 칩
      ⑤ 착용샷 이미지 3장(출처 도메인 표기, 클릭 시 원본 페이지로 이동)
      ⑥ 안내 문구 2종(개인차 안내 / 검색 이미지는 각 사이트 저작물이므로 재배포 금지)
      ⑦ `[공유 카드 만들기]` `[링크 복사]` `[다시 추천받기]`
    - 공유 카드: ①~④와 서비스명만 담은 별도 영역. 외부 이미지를 넣지 않는다 (캔버스 오염 방지)
- **사용자가 할 수 있는 행동**: 조건 선택, 추천 실행, 결과 저장, 조건 변경 후 재실행

## 5.2 결과 단독 화면 (Should · `?id=결과ID`)

- **화면 목적**: 공유받은 링크로 특정 결과만 열어 본다.
- **주요 구성 요소**: 결과 영역과 동일, 입력 폼 대신 `[나도 추천받기]` 버튼
- **사용자가 할 수 있는 행동**: 결과 열람, 메인으로 이동

# 6. 입력 → 처리 → 결과

## 입력

클라이언트가 서버로 넘기는 객체:

```json
{
  "mbti": "ENFP",
  "gender": "여성",
  "ageGroup": "고등학생",
  "bodyType": "보통",
  "season": "가을",
  "occasion": "발표·면접",
  "preferStyle": "미니멀"
}
```

- 7개 항목 모두 필수. 하나라도 비면 버튼이 눌리지 않고 해당 항목이 강조된다.
- 로그인·이름·개인정보는 받지 않는다.

## 처리

1. `google.script.run.withSuccessHandler(...).getRecommendation(input)` 호출
2. 서버에서 입력값 검증 (허용된 값 목록에 있는지 확인 — 프롬프트 주입 방지)
3. `MBTI_STYLE` 시트에서 `mbti`로 행 조회 → `core_colors`, `avoid_colors`, `pattern`, `fit`, `style_tags`, `keyword` 확보
4. 기준 데이터 + 사용자 입력을 하나의 프롬프트로 조합
5. `UrlFetchApp`으로 Gemini API 호출 (`responseMimeType: "application/json"` + `responseSchema`로 형식 고정)
6. 응답 JSON 파싱. 실패하면 1회 재시도 후에도 실패 시 오류 반환
7. `image_query`로 이미지 검색 (캐시 먼저 조회 → 없으면 Custom Search 호출 → 결과를 캐시에 저장)
8. `LockService`로 잠금 후 `RECOMMEND_LOG`에 한 행 기록, `result_id` 발급
9. 결과 객체 반환

API 키는 모두 **스크립트 속성(PropertiesService)** 에 저장하고 코드·HTML에 하드코딩하지 않는다.

## 결과

서버가 반환하는 객체:

```json
{

  "style_direction": "차분한 톤에 포인트 하나만 두는 방향이 잘 어울립니다. ...",
  "reason": "ENFP의 활동적인 인상에 발표·면접 상황의 단정함을 더하려면 ...",
  "outfit": {
    "top": "아이보리 셔츠",
    "bottom": "다크 네이비 슬랙스",
    "outer": "베이지 트렌치코트",
    "shoes": "브라운 로퍼",
    "accessory": "얇은 실버 목걸이",
    "color_combo": "아이보리 + 네이비 + 브라운"
  },
  "keywords": ["미니멀", "가을 발표룩", "네이비 슬랙스"],
  "images": [
    { "url": "https://...", "page": "https://...", "domain": "example.com" }
```

# 7. 데이터

Google Sheets 1개 파일, 시트 3개로 구성한다.

## 시트 1 — `MBTI_STYLE` (마스터 데이터, 16행)

| 열 | 설명 | 예시 |
|---|---|---|
| `mbti` | 16유형 코드 (키) | ENFP |
| `keyword` | 성향 키워드 3개 | 활발한, 자유로운, 표현적인 |
| `base_color` | 팀이 정한 대표 색 분류 (원본 값, 프롬프트에는 넣지 않음) | Bright |
| `core_colors` | 프롬프트에 넣을 실제 색 이름 3개 | 코랄, 옐로우, 터콰이즈 |
| `avoid_colors` | 피하면 좋은 색상 | 탁한 카키, 형광 |
| `pattern` | 어울리는 패턴 | 잔잔한 체크, 무지 |
| `fit` | 어울리는 핏 | 세미 오버핏 |
| `style_tags` | 대표 스타일 태그 | 캐주얼, 러블리 |
| `hair_tip` | 헤어 참고 | 볼륨 있는 웨이브 |
| `note` | 보조 설명 | 포인트 아이템 1개로 개성 표현 |

> **현재 상태: 16행 + DEFAULT 행 작성 완료** (`MBTI_STYLE_시드데이터.xlsx`). 구글 스프레드시트로 가져오기만 하면 된다.
>
> `base_color` / `pattern` / `fit` / `style_tags`는 팀이 직접 정한 원본 값이고, 나머지 열은 프롬프트 품질을 위해 보강한 값이다. `base_color`가 `Mixed`·`Bright`처럼 색 이름이 아닌 분류값이라 AI가 매번 다르게 해석하므로, 프롬프트에는 반드시 `core_colors`를 넣는다.
>
> MBTI와 패션 취향의 상관관계는 검증된 연구가 없다. 팀이 정의한 규칙임을 전제로 하고, 판단 근거를 `note`에 남긴다.

## 시트 2 — `RECOMMEND_LOG` (결과 누적)

`result_id` / `timestamp` / `mbti` / `gender` / `age_group` / `body_type` / `season` / `occasion` / `prefer_style` / `style_direction` / `reason` / `outfit_json` / `keywords` / `image_urls` / `latency_ms` / `status`

축적 목적: 어떤 조건 조합이 많은지, 어떤 응답이 실패했는지 분석해 프롬프트를 개선한다.

## 시트 3 — `IMAGE_CACHE` (이미지 검색 캐시)

`query` / `image_urls` / `cached_at`

같은 검색어 재사용으로 Custom Search 무료 한도(하루 100회)를 아낀다.

# 8. AI 기능

- **AI의 역할**: MBTI 기준 데이터와 사용자 조건을 종합해 상황에 맞는 코디 한 벌을 구성하고, 그 이유를 학생이 이해할 수 있는 말로 설명한다.
- **입력**: 시트에서 조회한 MBTI 기준 데이터 + 사용자가 고른 7개 조건
- **처리**: 아래 구조의 프롬프트로 1회 호출

```
[역할] 너는 중·고등학생에게 스타일을 제안하는 패션 코디네이터다.

[기준 데이터]
MBTI: {mbti} / 성향 키워드: {keyword}
어울리는 색: {core_colors} / 피할 색: {avoid_colors}
패턴: {pattern} / 핏: {fit} / 스타일 태그: {style_tags}

[사용자 조건]
성별 {gender}, {ageGroup}, 체형 {bodyType}, 계절 {season},
상황 {occasion}, 선호 스타일 {preferStyle}

[작성 규칙]
- 학생이 실제로 구할 수 있는 옷으로 구성한다. 고가 브랜드명은 쓰지 않는다.
- 계절과 상황을 반드시 반영한다. (교복 규정에 어긋나는 제안 금지)
- style_direction은 2~3문장, reason은 2~3문장으로 쓴다.
- 외모 평가나 체형 지적은 하지 않는다. 체형은 '어울리는 핏'으로만 언급한다.
- image_query는 이미지 검색에 쓸 한국어 검색어 한 줄로 쓴다.
  (예: "가을 여성 미니멀 발표룩 슬랙스 코디")
- 지정한 JSON 형식만 출력한다.
```

- **결과**: `style_direction`, `reason`, `outfit`(6개 항목), `keywords`(3개), `image_query`
- **사용할 모델**: `gemini-2.5-flash` (`responseMimeType: application/json` + `responseSchema` 사용)
- AI를 쓰지 않는 부분: 데이터 조회, 저장, 이미지 검색, 화면 렌더링

# 9. 기술 구성

| 항목 | 선택 | 비고 |
|---|---|---|
| Frontend | Apps Script HTML Service (HTML + CSS + Vanilla JS) | 단일 페이지 |
| Backend | Google Apps Script (`Code.gs`) | `doGet`, `getRecommendation` |
| Database | Google Sheets (시트 3개) | 별도 DB 없음 |
| Authentication | 없음 | 배포 시 "모든 사용자" 액세스 |
| Storage | 없음 (이미지는 외부 URL 참조) | |
| AI | Gemini API (`gemini-2.5-flash`) | `UrlFetchApp` 호출 |
| External API | Google Custom Search JSON API (`searchType=image`) | 무료 100회/일 → 캐시 필수. 응답의 `image.contextLink`를 원본 페이지 링크로 저장 |
| 공유 카드 생성 | html2canvas 1.4.1 (CDN) | 외부 이미지 제외 영역만 캡처 |
| 비밀값 관리 | PropertiesService 스크립트 속성 (`GEMINI_API_KEY`, `CSE_API_KEY`, `CSE_ID`) | |
| Deployment | Apps Script 웹 앱 배포 → 링크를 QR코드로 변환 | |

**왜 Next.js/Supabase가 아닌가**: 워크시트의 동작 흐름이 이미 `google.script.run` + 시트 조회를 전제로 설계되어 있고, 팀이 앱스 스크립트 유지를 선택했다. 서버 배포·인증 설정 없이 링크 하나로 학생에게 배포할 수 있어 해커톤 시간 안에 완성 가능성이 가장 높다.

**알아둘 제약**

- `UrlFetchApp` 응답 대기가 길어지면 클라이언트가 먼저 끊길 수 있다 → 프롬프트를 짧게 유지하고 `max_output_tokens`를 제한한다.
- HTML Service는 샌드박스 iframe이라 `localStorage`·파일 다운로드가 막힐 수 있다 → 결과 공유는 "이미지 길게 눌러 저장" + "결과 링크 복사"를 기본 경로로 둔다.
- 학급 동시 접속(30명)은 Gemini 분당 요청 한도에 걸릴 수 있다 → 429 응답 시 2초 후 1회 재시도하고, 실패하면 "잠시 후 다시 눌러주세요"로 안내한다.

# 11. 예외 상황

| 상황 | 처리 |
|---|---|
| 조건을 다 고르지 않고 버튼 클릭 | 버튼 비활성 유지, 빈 항목에 빨간 테두리와 "선택해 주세요" 표시 |
| Gemini 응답이 JSON이 아님 | 서버에서 1회 재시도. 그래도 실패하면 "추천을 만들지 못했어요. 다시 시도해 주세요" + 재시도 버튼 |
| Gemini 429 / 할당량 초과 | 2초 후 1회 재시도, 실패 시 "지금 이용자가 많아요. 잠시 후 다시 눌러주세요" |
| 응답 지연 (15초 초과) | "분석 중..." 유지, 30초 초과 시 오류 화면으로 전환하고 버튼 복구 |
| 이미지 검색 실패 / 한도 초과 | 이미지 영역을 숨기고 키워드 텍스트만 표시. 추천 결과 자체는 정상 노출 |
| 공유 카드 캡처 실패 (`toDataURL` 예외) | 카드 영역에 외부 이미지가 섞였는지 확인. 실패 시 "결과 텍스트 복사" 버튼으로 대체 |
| 클립보드 API 차단 (샌드박스) | `document.execCommand('copy')` 폴백 사용 |
| 학생이 검색 이미지를 SNS에 올리려 함 | 검색 이미지에는 저장 버튼을 두지 않는다. 공유는 우리가 만든 카드로만 유도하고, 이미지 영역에 재배포 금지 문구를 표기 |
| 이미지 URL이 깨짐 | `onerror`로 해당 이미지만 제거 |
| 시트에 해당 MBTI 행 없음 | 기본값 행(`DEFAULT`)으로 대체하고 로그 `status`에 `fallback` 기록 |
| 시트 저장 실패 | 사용자에게는 결과를 정상 표시하고, 저장 실패만 로그에 남긴다 (결과 표시를 막지 않는다) |
| 동시 접속 중 저장 충돌 | `LockService.getScriptLock()` 으로 쓰기 구간 잠금 (대기 10초) |
| 부적절한 결과 문구 생성 | 프롬프트에 외모 평가 금지 규칙 명시 + 결과 하단 신고/피드백 안내 문구 |

# 12. 완료 기준

1. QR코드를 스캔하면 로그인 없이 3초 안에 입력 화면이 뜬다.
2. 7개 조건을 모두 선택하면 버튼이 활성화되고, 하나라도 비면 활성화되지 않는다.
3. 버튼을 누르면 "분석 중..."이 뜨고, 20초 안에 결과가 표시된다.
4. 결과에는 스타일 방향(2~3문장), 코디 표 6개 항목(상의·하의·아우터·신발·액세서리·색상 조합), 추천 이유가 모두 채워져 있다.
5. **MBTI만 바꾸고 나머지를 동일하게 두면 코디 항목 중 최소 2개가 달라진다.**
6. **계절을 여름 → 겨울로 바꾸면 아우터 항목의 내용이 달라진다.**
7. **상황을 일상 → 발표·면접으로 바꾸면 상의 또는 하의가 더 단정한 아이템으로 바뀐다.**
8. 추천을 1회 실행할 때마다 `RECOMMEND_LOG`에 정확히 1행이 추가되고, 입력 7개 값과 결과 텍스트가 모두 들어 있다.
9. 결과 화면 하단에 "MBTI 기반 추천은 참고용이며 개인차가 있습니다" 문구가 항상 보인다.
10. 인터넷을 끊고 버튼을 누르면 앱이 멈추지 않고 오류 안내와 재시도 버튼이 나온다.
11. 스마트폰 세로 화면에서 가로 스크롤 없이 입력과 결과를 모두 볼 수 있다.
12. (Should) 착용샷 이미지가 3장 보이고, 검색 실패 시에도 결과 텍스트는 정상 표시된다.
13. (Should) 서로 다른 학생 3명이 연속으로 실행해도 오류 없이 3행이 저장된다.
14. (Should) `[공유 카드 만들기]`를 누르면 3초 안에 카드 이미지가 뜨고, 스마트폰에서 길게 눌러 사진첩에 저장된다.
15. (Should) 카드 이미지에 검색해 온 착용샷이 포함되어 있지 않다.
16. (Should) 착용샷 이미지를 누르면 원본 페이지가 새 탭에서 열린다.

# 13. 개발 순서

**0단계 — 데이터 준비 (코딩 전, 팀 전원)**
스프레드시트 생성 → `MBTI_STYLE` 헤더 9열 작성 → 16유형 행 채우기(1인당 4유형) → `DEFAULT` 행 1개 추가 → `RECOMMEND_LOG`, `IMAGE_CACHE` 헤더 생성.

**1단계 — 프로젝트 뼈대**
스프레드시트에서 확장 프로그램 → Apps Script. `Code.gs`, `Index.html` 생성. `doGet()`에서 `HtmlService.createTemplateFromFile('Index')` 반환. 배포 후 빈 화면이 뜨는 것 확인.

**2단계 — 입력 폼**
`Index.html`에 7개 선택 항목과 버튼 구현. 모두 선택되어야 버튼 활성화. 모바일 우선 CSS(1단 → 넓은 화면에서 2단).

**3단계 — 시트 조회**
`getStyleRow(mbti)` 작성. `getRecommendation()`이 조회 결과를 그대로 반환하도록 임시 연결해 `google.script.run` 왕복 확인.

**4단계 — Gemini 연동**
스크립트 속성에 `GEMINI_API_KEY` 저장 → `callGemini(prompt)` 작성 → `responseSchema`로 JSON 형식 고정 → 파싱 실패 시 1회 재시도.

**5단계 — 결과 렌더링**
반환 JSON을 결과 영역에 그린다. 스타일 방향, 코디 표, 추천 이유, 안내 문구. 로딩·오류 상태 UI 포함.

**6단계 — 로그 저장**
`saveLog()` 작성. `LockService` 잠금 후 `appendRow`. `result_id` 발급. 저장 실패가 화면 표시를 막지 않도록 try/catch 분리.

**7단계 — 이미지 검색 (Should)**
`CSE_API_KEY`, `CSE_ID` 저장 → `searchImages(query)` 작성 → `IMAGE_CACHE` 먼저 조회 → 없을 때만 API 호출 후 캐시 저장 → 결과 하단에 3장 렌더링.

**8단계 — 공유 (Should)**
html2canvas CDN 추가 → 카드 전용 영역(`#card`, 외부 이미지 없음) 마크업 → `toDataURL`로 PNG 생성 후 `<img>`로 표시(길게 눌러 저장) → 데스크톱용 `download` 링크 병행 → `?id=` 파라미터로 결과 단독 화면 렌더링 → `execCommand('copy')` 폴백을 쓴 링크 복사 버튼.

**9단계 — 예외 처리와 문구 점검**
11장의 표를 하나씩 재현해 확인. 프롬프트의 금지 규칙(외모 평가·교복 규정)이 지켜지는지 5회 이상 샘플 검수.

**10단계 — 배포와 테스트**
웹 앱 배포(실행: 나, 액세스: 모든 사용자) → 링크를 QR코드로 변환 → 팀원 4명이 서로 다른 기기에서 각각 2회씩 실행 → 12장의 완료 기준 1~13번을 순서대로 확인 → `RECOMMEND_LOG`에 8행이 쌓였는지 확인.

**AI 개발 도구 사용 시**: 이 문서 전체를 붙여넣고 "0단계 데이터는 이미 준비되어 있으니 1단계부터 시작해 줘. 단계마다 파일 전체 코드를 주고, 내가 확인한 뒤 다음 단계로 넘어가자"라고 요청하면 된다.
